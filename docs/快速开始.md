# 15 分钟快速开始

> **【说明】适用对象与完成标准**
>
> - **适用对象**：第一次使用实验室服务器的普通用户。
> - **前置条件**：已获得用户名、服务器地址或别名、管理员确认的 SSH 指纹，以及公钥提交渠道。
> - **完成标准**：能够通过 SSH 登录，确认自己的身份，在个人 `/data` 目录创建文件，并能启动和恢复一个 `tmux` 会话。

这是一条最短上手路径。完成本页后，再按需要阅读 VS Code、Conda、存储和网络等专题文档；不需要在第一次登录前通读整个知识库。

## 开始前需要拿到的信息

| 信息 | 用途 | 从哪里获取 |
| --- | --- | --- |
| `<username>` | 登录服务器时使用的账户名 | 管理员开户后提供 |
| `<server_address>` | SSH 连接地址 | 管理员私下提供 |
| `<server_alias>` | 本机自定义的简短名称 | 可以自定义，例如 `server-a` |
| SSH 指纹 | 第一次登录时核对服务器身份 | 管理员私下提供 |
| 公钥提交渠道 | 把 SSH 公钥交给管理员 | 入组交接信息 |
| `/data/<username>` | 存放数据和项目文件 | 管理员创建并确认权限 |
| 管理员联系方式 | 开户、权限和故障反馈 | 入组交接信息 |

> **【警告】连接信息不公开**
>
> 服务器地址、真实主机名、网络账户、BMC 地址和管理员联系方式不写入公开文档。管理员应通过受控的私有清单或入组交接信息提供。

## 1. 准备 SSH 密钥

先检查本机是否已经有可用公钥：

```bash
ls -l ~/.ssh/*.pub
```

如果已有 `id_ed25519.pub`，先确认相应私钥仍在且可用；可以继续使用，不要覆盖现有私钥。如果没有，再生成：

```bash
ssh-keygen -t ed25519 -C "your_name@lab"
```

查看需要提交给管理员的公钥：

```bash
cat ~/.ssh/id_ed25519.pub
```

只发送以 `.pub` 结尾的公钥，不要发送私钥。完整说明参见 [SSH 登录](ssh登录.md)。

## 2. 提交开户信息

向管理员提交：

```text
姓名：
希望使用的用户名：
SSH 公钥：
所属项目或需要加入的用户组：
```

管理员完成开户后，应返回用户名、服务器地址、SSH 指纹、个人数据目录和故障反馈渠道。如果其中任意一项缺失，先补齐信息再继续。

## 3. 配置本机 SSH

编辑本机 `~/.ssh/config`：

```sshconfig
Host <server_alias>
    HostName <server_address>
    User <username>
    Port 22
    IdentityFile ~/.ssh/id_ed25519
    IdentitiesOnly yes
```

这里的 `server-a` 之类名称只是本机示例别名，不是真实服务器名。

## 4. 第一次登录并核对身份

连接服务器：

```bash
ssh <server_alias>
```

第一次登录时，先核对提示中的 SSH 指纹与管理员提供的信息一致，再输入 `yes`。登录后执行：

```bash
hostname
whoami
pwd
```

成功时应满足：

- `whoami` 输出管理员分配的 `<username>`。
- `pwd` 通常输出 `/home/<username>`。
- `hostname` 与管理员提供的目标服务器一致。

任何一项不一致都应停止操作并联系管理员，不要继续写入数据。

## 5. 检查个人数据目录

确认目录存在并测试写入：

```bash
ls -ld "/data/$USER"
write_test=$(mktemp "/data/$USER/.write_test.XXXXXX") && rm -- "$write_test"
```

目录检查和临时文件创建、删除均成功，说明当前用户可在该目录写入。`mktemp` 使用独一的文件名，避免误删原有同名文件；`$USER` 若与 `whoami` 不同，应改用管理员确认的账户名。如果失败，把以下输出发给管理员：

```bash
id
ls -ld /data "/data/$USER"
```

不要自行对 `/data` 根目录执行 `sudo chown -R` 或 `chmod 777`。

## 6. 测试长时间会话

新建测试会话：

```bash
tmux new -s hello
```

在会话中执行 `hostname`，然后按 `Ctrl-b`、再按 `d` 退出。重新进入：

```bash
tmux attach -t hello
```

确认能够恢复后，输入 `exit` 关闭测试会话。完整用法参见 [终端与 tmux](终端.md)。

## 7. 检查基础网络

```bash
curl -I --max-time 10 https://www.baidu.com
```

看到目标站点的 HTTP 状态行，说明对该站点完成了一次请求；403、407、5xx 等仍需结合状态码排查，也不能由此推定所有外网服务都可用。如果失败，先阅读 [一般网络连接](一般网络连接.md)；访问 GitHub、软件源或 AI 服务仍失败时，再阅读 [代理网络连接](代理网络连接.md)。

## 完成检查

| 检查项 | 成功现象 |
| --- | --- |
| SSH 登录 | 能进入服务器 shell，且身份与目标主机正确 |
| 数据目录 | 能在 `/data/<username>` 创建并删除测试文件 |
| 长时间会话 | 能创建、断开并恢复 `tmux` 会话 |
| 基础网络 | `curl -I` 返回 HTTP 状态行 |

完成后，推荐继续阅读 [VS Code 连接服务器](vscode连接.md)、[大容量存储](大容量存储.md) 和 [Conda 环境](conda环境.md)。

命令语义参照 [OpenSSH 配置手册](https://man.openbsd.org/ssh_config)、[tmux 入门](https://github.com/tmux/tmux/wiki/Getting-Started) 和 [curl 手册](https://curl.se/docs/manpage.html)。
