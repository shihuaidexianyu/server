# 异常处理

服务器异常通常包括内存耗尽、磁盘写满、网络中断、服务不可用、SSH 无法登录等。处理异常时应先保存现场信息，再采取影响较小的恢复动作。

> **【说明】适用对象与完成标准**
>
> - **适用对象**：遇到任务、磁盘、网络或登录异常的普通用户；服务恢复和系统级日志处理由管理员负责。
> - **前置条件**：记录发生时间、失败命令和完整报错，不要先重启或删除现场数据。
> - **所需权限**：资源查看通常不需要 `sudo`；`dmesg`、完整 `journalctl` 和服务操作可能需要管理员权限。
> - **完成标准**：能够判断问题属于内存、磁盘、SSH 或网络中的哪一类，并向管理员提供足够的诊断信息。

## OOM 及其防止

OOM 是 out of memory 的缩写，表示系统内存不足。严重 OOM 可能导致服务器卡死、SSH 无响应、任务被系统杀死，甚至影响其他用户。

原部署记录称安装了 `earlyoom`；是否存在、是否正在运行及阈值必须实机确认。它根据可用内存/交换空间阈值和进程评分提前终止进程，不能保证整机始终响应，也不同于内核 OOM killer。

查看 `earlyoom` 状态：

```bash
systemctl status earlyoom
```

如果提示权限不足，普通用户应记录报错并联系管理员，不要为了查看日志索要长期 sudo 权限。

查看日志：

```bash
journalctl -u earlyoom --since "1 day ago"
```

## 查看内存占用

实时查看：

```bash
top  # 系统常见工具；已安装时也可用 htop 或 btop
```

命令行查看：

```bash
free -h
ps aux --sort=-%mem | head -20
```

判断整机可分配内存优先看 `free` 的 `available`，`free` 很少不一定表示内存耗尽。进程 `%MEM` 也不是该用户所有进程相加后的精确物理内存（共享页可能重复计入）。

查看某个用户的进程：

```bash
ps -u <username> -o pid,ppid,%mem,%cpu,cmd --sort=-%mem | head -20
```

## 任务被杀后的判断

如果程序突然退出，先检查是否是 OOM：

```bash
dmesg -T | grep -i -E 'killed process|out of memory|oom'
journalctl --since "1 hour ago" | grep -i -E 'earlyoom|out of memory|killed process'
```

部分系统限制普通用户读取内核或系统日志；出现 `Operation not permitted` 或无权访问时，由管理员执行这些命令。

只有日志中的时间、PID/命令与本任务吻合，才有证据说明它被 OOM/earlyoom 终止；选中的受害进程未必是造成全局压力的唯一来源。单独的 `Killed` 或退出码 137 只提示 SIGKILL 等可能性，不足以确认 OOM。容器或作业的 cgroup 内存上限也可能先触发 OOM，即使整机还有余量；管理员可结合对应组的 `memory.max` 与 `memory.events`（cgroup v2）核查。

## 降低 OOM 风险

- 先用小样本测试脚本。
- 控制并行进程数。
- 不要同时开太多 Jupyter kernel。
- 训练模型时设置合理 batch size。
- 数据处理时避免一次性读入全部大文件。
- 使用 `tmux` 保持任务可观察。
- 在多人共享服务器上提前沟通大任务。

## 磁盘空间异常

查看磁盘空间：

```bash
df -h /data "$HOME"
df -i /data "$HOME"
findmnt --target /data -o TARGET,SOURCE,OPTIONS
```

字节空间、inode、只读挂载和用户配额可能分别导致写入失败；若部署要求 `/data` 独立挂载，还应查 `findmnt --mountpoint /data`。

查看目录大小：

```bash
du -sh /data/<username> "$HOME"
```

查找大文件：

```bash
find /data/<username> -xdev -type f -size +10G -print
```

不要直接删除不属于自己的数据。需要清理共享目录时，先确认负责人。

## SSH 无法登录

常见原因：

- 本机网络不通。
- 服务器 SSH 服务异常。
- 防火墙阻断。
- 公钥未配置或权限错误。
- 用户账户被禁用。

排查命令：

```bash
ssh -vvv <server_alias>
ping <server_address>
nc -vz <server_address> 22
```

ping 失败可能只是 ICMP 被禁；端口可达也不证明 SSH 密钥认证成功。SSH 配置详见 [SSH 登录](ssh登录.md)。

## 网络异常

普通校内网络连接参见 [一般网络连接](一般网络连接.md)。

需要代理访问外部网络时，参见 [代理网络连接](代理网络连接.md)。

检查命令：

```bash
curl -I --max-time 10 https://www.baidu.com
curl --max-time 10 https://ipinfo.io/ip
```

如果开启代理后仍失败，检查环境变量：

```bash
env | cut -d= -f1 | grep -i proxy
```

## 处理异常时要记录的信息

向管理员反馈问题时，建议提供：

- 服务器主机名。
- `<username>`。
- 发生时间。
- 正在运行的命令或脚本。
- 错误截图或日志。
- `df -h`、`free -h`、`hostname` 的输出。
- 是否使用代理、Conda、VS Code 或 tmux。

反馈时补退出码、时间范围与任务 PID；发到公开渠道前遮盖凭据、内部地址和私有路径。不要为验证 OOM 主动制造内存耗尽，也不要关闭 earlyoom 来试错。

依据：[earlyoom 作者 README](https://github.com/rfjakob/earlyoom)、[procps free 手册](https://man7.org/linux/man-pages/man1/free.1.html)、[内核 cgroup v2 文档](https://www.kernel.org/doc/html/latest/admin-guide/cgroup-v2.html)。
