# 异常处理

服务器异常通常包括内存耗尽、磁盘写满、网络中断、服务不可用、SSH 无法登录等。处理异常时应先保存现场信息，再采取影响较小的恢复动作。

## OOM 及其防止

OOM 是 out of memory 的缩写，表示系统内存不足。严重 OOM 可能导致服务器卡死、SSH 无响应、任务被系统杀死，甚至影响其他用户。

服务器使用 `earlyoom` 守护服务在系统完全崩溃前提前终止部分进程，以降低整机失去响应的概率。

查看 `earlyoom` 状态：

```bash
systemctl status earlyoom
```

查看日志：

```bash
journalctl -u earlyoom --since "1 day ago"
```

## 查看内存占用

实时查看：

```bash
btop # 更美观的htop/top
```

命令行查看：

```bash
free -h
ps aux --sort=-%mem | head -20
```

查看某个用户的进程：

```bash
ps -u <username> -o pid,ppid,%mem,%cpu,cmd --sort=-%mem | head -20
```

## 任务被杀后的判断

如果程序突然退出，先检查是否是 OOM：

```bash
dmesg -T | grep -i -E 'killed process|out of memory|oom'
journalctl --since "1 hour ago" | grep -i -E 'earlyoom|out of memory|killed process'
```

如果日志里出现 `Killed process` 或 `earlyoom` 相关信息，说明任务很可能因为内存占用过高被终止。

## 降低 OOM 风险

- 先用小样本测试脚本。
- 控制并行进程数。
- 不要同时开太多 Jupyter kernel。
- 训练模型时设置合理 batch size。
- 数据处理时避免一次性读入全部大文件。
- 使用 `tmux` 保持任务可观察。
- 在多人共享服务器上提前沟通大任务。

## 磁盘空间异常

查看磁盘空间：

```bash
df -h
```

查看目录大小：

```bash
du -sh /data/*
du -sh ~/*
```

查找大文件：

```bash
find /data -type f -size +10G -print
```

不要直接删除不属于自己的数据。需要清理共享目录时，先确认负责人。

## SSH 无法登录

常见原因：

- 本机网络不通。
- 服务器 SSH 服务异常。
- 防火墙阻断。
- 公钥未配置或权限错误。
- 用户账户被禁用。

排查命令：

```bash
ssh -vvv <server_alias>
ping <server_address>
nc -vz <server_address> 22
```

SSH 配置详见 [ssh登录.md](ssh登录.md)。

## 网络异常

普通校内网络连接参见 [一般网络连接.md](一般网络连接.md)。

需要代理访问外部网络时，参见 [代理网络连接.md](代理网络连接.md)。

检查命令：

```bash
curl -I https://www.baidu.com
curl ipinfo.io
```

如果开启代理后仍失败，检查环境变量：

```bash
env | grep -i proxy
```

## 处理异常时要记录的信息

向管理员反馈问题时，建议提供：

- 服务器主机名。
- `<username>`。
- 发生时间。
- 正在运行的命令或脚本。
- 错误截图或日志。
- `df -h`、`free -h`、`hostname` 的输出。
- 是否使用代理、Conda、VS Code 或 tmux。

信息越完整，定位问题越快。
