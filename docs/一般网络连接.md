# 一般网络连接

一般网络连接指不依赖代理的校内网络或常规互联网访问。当前可在实验室公共或指定账户（如 `zhangruyuan`）下使用 `its` 脚本进行交互式连接。

## 适用场景

一般网络连接适合：

- 访问校内服务。
- 下载不需要代理的软件包。
- 连接实验室内部资源。
- 测试服务器基础联网状态。

如果需要访问 GitHub、npm、部分国外软件源或 AI 工具相关服务，可能需要使用代理网络，参见 [代理网络连接.md](代理网络连接.md)。

## 使用 its 脚本

在实验室公共或指定账户下运行：

```bash
its
```

脚本会进入交互式流程，根据提示输入账号和密码。

当前账号信息由管理员通过安全方式提供：

```text
账号：由管理员提供
密码：不写入共享文档
```

不建议把真实密码明文写在共享文档中。如果必须记录，应放在受控的密码管理工具或管理员私有文档中。

## 检查网络是否可用

检查域名解析：

```bash
nslookup www.baidu.com
```

检查 HTTP 访问：

```bash
curl -I https://www.baidu.com
```

查看出口 IP：

```bash
curl ipinfo.io
```

检查路由：

```bash
ip route
```

## 常见问题

### 域名解析失败

现象通常是 `Could not resolve host`。可以检查：

```bash
cat /etc/resolv.conf
resolvectl status
```

### 能 ping IP 但不能访问域名

通常是 DNS 问题。先记录错误信息，再联系管理员处理。

### 普通网站可访问，但 GitHub 等不可访问

这通常不是服务器故障，可能需要代理。参见 [代理网络连接.md](代理网络连接.md)。

### 只有某个用户无法联网

检查该用户是否设置了错误代理变量：

```bash
env | grep -i proxy
```

如有异常，可以先关闭代理：

```bash
poff
```

如果 `poff` 不存在，说明当前 shell 没有继承全局 Bash 配置，参见 [bash继承.md](bash继承.md)。

## 反馈网络问题时需要提供

- 服务器主机名。
- 当前 `<username>`。
- 访问的目标地址。
- 失败命令和完整报错。
- `curl -I` 或 `ping` 的结果。
- 是否开启过代理。
