# 一般网络连接

一般网络连接指不依赖代理的校内网络或常规互联网访问。以下沿用部署记录中通过 `its` 脚本交互认证的流程；接口和认证方式以部署版本为准，实际账户由管理员通过私有交接信息提供。

> **【说明】适用对象与完成标准**
>
> - **适用对象**：需要在服务器上访问校内服务或普通互联网的用户。
> - **前置条件**：已经 SSH 登录，并从管理员处确认应使用的网络认证账户和凭据。
> - **完成标准**：域名可以解析，`curl -I` 能返回 HTTP 状态行，且不需要代理的校内资源可以访问。

## 适用场景

一般网络连接适合：

- 访问校内服务。
- 下载不需要代理的软件包。
- 连接实验室内部资源。
- 测试服务器基础联网状态。

如果需要访问 GitHub、npm、部分国外软件源或 AI 工具相关服务，可能需要使用代理网络，参见 [代理网络连接](代理网络连接.md)。

## 使用 its 脚本

> **【警告】先确认实验室采用的认证方式**
>
> 管理员应在私有入组信息中明确：用户是在自己的账户运行 `its`，还是由管理员维护统一的认证会话。普通用户不要在未获授权时自行切换或共用其他人的 Linux 账户。

切换到管理员指定且已配置网络认证的账户或会话后运行：

```bash
its
```

按部署版帮助确认后，再根据交互提示输入网络账户信息。`its` 不是通用 Linux 命令；不要从名称推定脚本来源或把网络账户等同 Linux 登录账户。

如果当前 shell 提示 `its: command not found`，先执行：

```bash
type -t its
ps -p $$ -o comm=
```

把输出发给管理员确认脚本部署方式，不要从不明来源自行下载同名脚本。

当前账号信息由管理员通过安全方式提供：

```text
账号：<network_account>
密码：不写入共享文档
```

不建议把真实密码明文写在共享文档中。如果必须记录，应放在受控的密码管理工具或管理员私有文档中。

## 检查网络是否可用

检查域名解析：

```bash
getent ahosts www.baidu.com
```

检查 HTTP 访问：

```bash
curl --noproxy "*" -I --max-time 10 https://www.baidu.com
```

查看出口 IP：

```bash
curl --noproxy "*" --max-time 10 https://ipinfo.io/ip
```

检查路由：

```bash
ip route
```

## 常见问题

### 域名解析失败

现象通常是 `Could not resolve host`。可以检查：

```bash
cat /etc/resolv.conf
resolvectl status
```

### 能 ping IP 但不能访问域名

只有“域名解析失败”才直接指向解析层；ping 能通而 HTTP 失败也可能是端口策略、TLS、认证或目标服务故障。先记录具体错误，再联系管理员。

### 普通网站可访问，但 GitHub 等不可访问

先按 DNS、TCP、TLS 和 HTTP 状态逐层排查，也可能是目标服务故障或需要代理；不要仅凭一个网站失败就确定原因。参见 [代理网络连接](代理网络连接.md)。

### 只有某个用户无法联网

检查该用户是否设置了错误代理变量：

```bash
env | cut -d= -f1 | grep -i proxy
```

如有异常，可以先关闭代理：

```bash
poff
```

如果 `poff` 不存在，可能是 shell 类型、启动方式或函数尚未部署，参见 [Bash 继承](bash继承.md)。

## 反馈网络问题时需要提供

- 服务器主机名。
- 当前 `<username>`。
- 访问的目标地址。
- 失败命令和完整报错。
- `curl -I` 或 `ping` 的结果。
- 是否开启过代理。

## 下一步

如果你需要访问 GitHub、Hugging Face、npm、部分国外软件源，或使用 AI 命令行工具，完成校内网认证后继续阅读 [代理网络连接](代理网络连接.md)。

如果已经确认代理可用，但 AI CLI、npm、nvm 等工具仍不能联网，继续阅读 [AI 使用](AI使用.md)。

`--noproxy "*"` 是 curl 的单次直连检测；它不修改当前环境。HTTP 状态码须区分成功、认证要求与服务错误，IP 查询只描述这次请求的出口。诊断命令只打印代理变量名；需要检查值时在自己的终端查看，对外反馈先遮盖代理凭据和内部信息。

依据：[curl 官方手册](https://curl.se/docs/manpage.html) 的代理/NO_PROXY/HEAD 选项。
