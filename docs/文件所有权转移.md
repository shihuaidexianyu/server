# 文件所有权转移

Linux 中转移文件或目录所有权的主要命令是 `chown`。在服务器上，所有权转移常见于共享数据、修复下载文件归属、给新用户分配目录、整理 `/data` 存储等场景。

## 先理解所有者、用户组和权限

查看文件：

```bash
ls -l <file_path>
```

输出示例：

```text
-rw-r--r-- 1 alice lab 1234 Jul  8 10:00 result.txt
```

含义如下：

- `alice` 是所有者。
- `lab` 是用户组。
- `-rw-r--r--` 是权限。
- 所有者、同组用户、其他用户分别拥有不同权限。

查看目录本身：

```bash
ls -ld <dir_path>
```

查看更详细信息：

```bash
stat <file_path>
```

## 基本用法

更改文件所有者：

```bash
sudo chown <username> <file_path>
```

同时更改所有者和用户组：

```bash
sudo chown <username>:<group_name> <file_path>
```

示例：

```bash
sudo chown alice result.txt
sudo chown alice:alice result.txt
```

## 递归修改目录

如果要把一个目录和里面所有内容都转给某个用户：

```bash
sudo chown -R <username>:<username> <dir_path>
```

`-R` 表示递归，影响目录下所有文件和子目录。使用前务必确认路径正确：

```bash
pwd
ls -ld <dir_path>
```

不要在不确认路径的情况下对 `/`、`/home`、`/data` 根目录直接执行递归 `chown`。

## 常用选项

| 选项 | 说明 | 示例 |
| --- | --- | --- |
| `-R` | 递归更改目录及其子内容 | `sudo chown -R alice:alice /data/alice` |
| `-v` | 显示详细更改过程 | `sudo chown -v alice file.txt` |
| `-c` | 只显示实际发生更改的项目 | `sudo chown -c alice file.txt` |
| `--from=当前所有者` | 只修改当前所有者匹配的文件 | `sudo chown --from=root alice file.txt` |

## 只改用户组

只改用户组可以使用：

```bash
sudo chown :<group_name> <file_path>
```

或：

```bash
sudo chgrp <group_name> <file_path>
```

共享项目目录中，经常需要把文件组设置为项目组：

```bash
sudo chgrp -R labgroup /data/project
```

## 修改权限

`chown` 只负责所有权，不负责读写执行权限。权限使用 `chmod` 修改：

```bash
chmod u+rw <file_path>
chmod g+rw <file_path>
chmod o-rwx <file_path>
```

常见目录权限：

```bash
chmod 700 /data/<username>
chmod 770 /data/project
```

含义：

- `700`：只有所有者可以读、写、进入。
- `770`：所有者和用户组可以读、写、进入，其他用户不能访问。

## 项目目录推荐设置

如果一个项目目录需要多人协作，可以使用同一个用户组：

```bash
sudo chown -R <owner_username>:<project_group> /data/project
sudo chmod -R g+rwX /data/project
```

为了让新建文件自动继承目录用户组，可以给目录设置 setgid 位：

```bash
sudo find /data/project -type d -exec chmod g+s {} \;
```

其中 `X` 表示只给目录和已有可执行文件加执行权限，比直接 `chmod -R g+rwx` 更安全。

## 转移下载数据

如果管理员或其他用户代下载了数据，转移给目标用户：

```bash
sudo chown -R <username>:<username> /data/<username>/dataset
```

然后让目标用户检查：

```bash
ls -ld /data/<username>/dataset
touch /data/<username>/dataset/write_test
rm /data/<username>/dataset/write_test
```

## 检查用户和组是否存在

执行前先检查：

```bash
id <username>
getent group <group_name>
```

如果用户或组不存在，`chown` 会失败，或者在某些场景下造成难以理解的数字 UID/GID。

## 常见错误

### Permission denied

说明当前用户没有权限。需要使用 `sudo` 或联系管理员。

### invalid user

说明用户名或用户组不存在。用 `id` 和 `getent group` 检查。

### 修改后仍然不能写入

可能是权限不足，而不是所有权问题。检查：

```bash
ls -ld <dir_path>
namei -l <dir_path>
```

`namei -l` 可以逐级显示路径权限，适合排查中间目录没有执行权限的问题。

## 安全提醒

- 不要递归修改系统目录，例如 `/bin`、`/usr`、`/etc`。
- 不要把公共软件目录改成普通用户可写，除非明确知道后果。
- 不要为了省事给目录 `chmod 777`。
- 大目录递归修改前先确认路径和文件数量。
- 对 `/data` 下共享目录的修改，应提前通知项目成员。
