# 大容量存储

原部署约定把大容量存储挂载在 `/data/` 下，实际挂载来源和容量须登录目标机核对。大数据集、中间结果、模型权重、影像处理输出等应优先放在 `/data`，不要长期占用系统盘或用户主目录。

> **【说明】适用对象与完成标准**
>
> - **适用对象**：需要保存数据、结果或共享项目文件的普通用户和项目负责人。
> - **前置条件**：管理员已经创建 `/data/<username>` 或项目目录。
> - **所需权限**：普通用户可在有写入/进入权限的目录内创建目录；创建 `/data` 下的开户目录和变更所有者按管理员流程处理。
> - **完成标准**：`findmnt` 显示预期挂载来源且空间充足，再能在自己的目录创建和删除测试文件。

## 查看挂载情况

检查 `/data` 是否存在：

```bash
ls -ld /data
```

查看磁盘容量：

```bash
df -h /data
```

查看文件系统类型和挂载来源：

```bash
findmnt --mountpoint /data -o TARGET,SOURCE,FSTYPE,OPTIONS
findmnt --target /data -o TARGET,SOURCE,FSTYPE,OPTIONS
```

`--mountpoint` 要求 `/data` 本身是挂载点；`--target` 显示承载该路径的文件系统。若部署确实要求 `/data` 独立挂载，却只查到 `/`，应暂停大数据写入并联系管理员。`df -h /data` 只显示所在文件系统，不能单独证明数据盘挂载成功；还可用 `df -i /data` 检查 inode。

## 推荐目录结构

个人目录：

```text
/data/<username>
```

项目目录：

```text
/data/project_name
```

共享数据集：

```text
/data/datasets/dataset_name
```

具体目录命名应尽量清楚，避免使用 `new`、`test`、`tmp2` 这类长期不可读名称。

## 创建个人目录

> **【警告】仅限管理员创建**
>
> 普通用户如果没有个人目录，应把用户名和 `ls -ld /data` 的输出发给管理员，不要自行修改 `/data` 根目录权限。

管理员可以为用户创建目录：

```bash
sudo mkdir -p /data/<username>
sudo chown <username>:<username> /data/<username>
sudo chmod 700 /data/<username>
```

用户检查是否可写：

```bash
write_test=$(mktemp /data/<username>/.write_test.XXXXXX) && rm -- "$write_test"
```

临时文件创建和删除均成功才表示目录可写；避免用固定测试文件名误删现有文件。若失败，执行 `id` 和 `ls -ld /data/<username>`，把完整输出发给管理员。

所有权转移细节参见 [文件所有权转移](文件所有权转移.md)。

## 创建项目共享目录

多人项目建议使用项目用户组：

```bash
sudo mkdir -p /data/project_name
sudo chown owner:project_group /data/project_name
sudo chmod 2770 /data/project_name
```

`2770` 中的 `2` 表示 setgid，新建文件会继承目录用户组。它不保证新文件可被同组成员写入；还需要合适的 umask 或管理员设置的默认 ACL。权限和组成员变更后应让成员重新登录并测试。

## 查看空间占用

查看 `/data` 下一级目录大小：

```bash
du -h --max-depth=1 /data | sort -h
```

普通用户可能看到部分目录的 `Permission denied`，这表示没有读取其他项目目录的权限，不一定是磁盘故障。

查看当前目录大小：

```bash
du -sh .
```

查找大文件：

```bash
find /data/<username> -xdev -type f -size +10G -print
```

## 数据移动

> **【危险】数据自负**
>
> 在执行 `rm -rf`、大目录 `mv` 或覆盖式 `rsync` 前，务必先执行 `pwd`、`ls -lah` 和 `df -h` 确认当前路径、目标路径和剩余空间。服务器未开启回收站机制，删除和覆盖操作通常不可逆。

同一服务器目录之间移动（跨文件系统的 `mv` 会复制后删除，不能当作瞬间完成的原子重命名）：

```bash
mv <source_path> <target_path>
```

跨服务器或从本地上传时，可以使用 `rsync`；两端都须安装它。先预览路径与变化，再传输，并保留未完成的大文件：

```bash
rsync -avhn --itemize-changes <local_dir>/ <server_alias>:/data/<username>/<target_dir>/
rsync -avh --progress --partial-dir=.rsync-partial <local_dir>/ <server_alias>:/data/<username>/<target_dir>/
```

从服务器下载到本地：

```bash
rsync -avhn --itemize-changes <server_alias>:/data/<username>/<target_dir>/ <local_dir>/
rsync -avh --progress --partial-dir=.rsync-partial <server_alias>:/data/<username>/<target_dir>/ <local_dir>/
```

源目录尾部 `/` 表示复制其内容，不带 `/` 通常会多保留一层目录。`-n` 是预览，不写目标文件；第二条才实际传输，仍会覆盖需更新的同名文件。`--partial-dir` 保存中断文件供重跑利用，目录应保持仅可信用户可写；这不是备份或完整性保证。重要结果可另外保存校验清单。

## 注意事项

- `/data` 不是无限空间，定期清理中间文件。
- 不要把临时缓存长期留在共享目录。
- 不要随意修改别人目录的权限和所有权。
- 删除大型数据前确认没有其它任务正在使用。
- 重要数据应有备份方案，不要把单台服务器当成唯一副本。
- 如果程序默认写入 `~/.cache` 或 `~/Downloads`，要注意系统盘可能被写满。

依据：[util-linux findmnt 手册](https://man7.org/linux/man-pages/man8/findmnt.8.html)、[rsync 官方手册](https://download.samba.org/pub/rsync/rsync.1)、[GNU mktemp](https://www.gnu.org/s/coreutils/manual/html_node/mktemp-invocation.html)。
