# 大容量存储

服务器的大容量存储统一挂载在 `/data/` 下。大数据集、中间结果、模型权重、影像处理输出等应优先放在 `/data`，不要长期占用系统盘或用户主目录。

## 查看挂载情况

检查 `/data` 是否存在：

```bash
ls -ld /data
```

查看磁盘容量：

```bash
df -h /data
```

查看文件系统类型和挂载来源：

```bash
findmnt /data
```

## 推荐目录结构

个人目录：

```text
/data/<username>
```

项目目录：

```text
/data/project_name
```

共享数据集：

```text
/data/datasets/dataset_name
```

具体目录命名应尽量清楚，避免使用 `new`、`test`、`tmp2` 这类长期不可读名称。

## 创建个人目录

管理员可以为用户创建目录：

```bash
sudo mkdir -p /data/<username>
sudo chown <username>:<username> /data/<username>
sudo chmod 700 /data/<username>
```

用户检查是否可写：

```bash
touch /data/<username>/write_test
rm /data/<username>/write_test
```

所有权转移细节参见 [文件所有权转移.md](文件所有权转移.md)。

## 创建项目共享目录

多人项目建议使用项目用户组：

```bash
sudo mkdir -p /data/project_name
sudo chown owner:project_group /data/project_name
sudo chmod 2770 /data/project_name
```

`2770` 中的 `2` 表示 setgid，新建文件会继承目录用户组，适合多人协作。

## 查看空间占用

查看 `/data` 下一级目录大小：

```bash
du -h --max-depth=1 /data | sort -h
```

查看当前目录大小：

```bash
du -sh .
```

查找大文件：

```bash
find /data -type f -size +10G -print
```

## 数据移动

!!! danger "数据自负"

    在执行 `rm -rf`、大目录 `mv` 或覆盖式 `rsync` 前，务必先执行 `pwd`、`ls -lah` 和 `df -h` 确认当前路径、目标路径和剩余空间。服务器未开启回收站机制，删除和覆盖操作通常不可逆。

本机目录之间移动：

```bash
mv <source_path> <target_path>
```

跨服务器或从本地上传时，推荐使用 `rsync`，中断后可以继续：

```bash
rsync -avh --progress <local_path> <server_alias>:/data/<username>/
```

从服务器下载到本地：

```bash
rsync -avh --progress <server_alias>:/data/<username>/<target_dir> <local_path>
```

## 注意事项

- `/data` 不是无限空间，定期清理中间文件。
- 不要把临时缓存长期留在共享目录。
- 不要随意修改别人目录的权限和所有权。
- 删除大型数据前确认没有其它任务正在使用。
- 重要数据应有备份方案，不要把单台服务器当成唯一副本。
- 如果程序默认写入 `~/.cache` 或 `~/Downloads`，要注意系统盘可能被写满。
