# 防火墙

实验室文档的目标策略是：只按需允许入站访问，SSH 使用管理员确认的端口（示例为 TCP 22）。目标策略不代表当前有效规则；实际开放端口需在部署机器上检查。这样做是为了减少被扫描、误访问和弱口令攻击的风险。即使服务器位于校内网络，也不能假设校内网络是可信环境。

> **【警告】管理员专用**
>
> - **适用对象**：负责服务器网络边界的管理员。
> - **前置条件**：确认有备用 SSH 会话或 BMC 恢复方式，并记录修改前规则。
> - **所需权限**：需要 `sudo`。
> - **完成标准**：SSH 仍可连接，目标端口只对预期来源开放，临时规则有负责人和关闭时间。

## 基本原则

- 默认不开放端口，只有明确需要时才开放。
- 优先限定来源地址/网段；UFW 网络规则不等同按远端 Linux 用户名授权。
- 临时调试端口用完后及时关闭。
- 不要把 Jupyter、TensorBoard、Web 服务等直接暴露到所有地址，优先使用 SSH 端口转发。
- 修改防火墙前先确认自己有备用登录方式，避免误操作把 SSH 也锁住。

## 查看防火墙状态

Ubuntu 上通常使用 `ufw` 管理防火墙：

```bash
sudo ufw status verbose
sudo ufw status numbered
```

`inactive` 只说明 UFW 未启用，不证明系统没有其它防火墙、上游 ACL 或容器网络规则。启用前先核对默认入站/出站策略、已有规则和真实 SSH 端口，留好恢复通道；以下仅是管理员检查后的示例：

```bash
sudo ufw --dry-run allow 22/tcp
# 审核计划与现有规则后，再分别允许真实 SSH 端口、启用 UFW
sudo ufw allow 22/tcp
sudo ufw enable
```

## 开放端口

临时开放一个端口时，先确认服务确实监听在该端口：

```bash
ss -lntp
```

仅对确认的来源开放 TCP 端口；下面以文档示例地址演示：

```bash
sudo ufw --dry-run allow from 192.0.2.25 to any port 8888 proto tcp
sudo ufw allow from 192.0.2.25 to any port 8888 proto tcp
```

`192.0.2.25` 是文档专用示例，须替换为服务器实际看见的来源地址（可能经过 NAT）。若已有 `allow 8888/tcp` 这类广泛规则，再加来源限定规则不会收窄旧规则，必须单独审查并移除广泛规则。

## 关闭端口

查看规则编号：

```bash
sudo ufw status numbered
```

按编号删除规则：

```bash
sudo ufw delete <rule_number>
```

编号会随删除改变，每删一条重新查看，IPv4/IPv6 条目也须分别核对。也可以按规则内容删除：

```bash
sudo ufw delete allow 8888/tcp
```

## 推荐做法：使用 SSH 端口转发

如果只是自己访问服务器上的 Jupyter、TensorBoard 或 Web UI，不建议开放公网或校内网端口。可以在本机执行：

```bash
ssh -N -o ExitOnForwardFailure=yes -L 127.0.0.1:<local_port>:127.0.0.1:<remote_port> <server_alias>
```

然后在本机浏览器打开：

```text
http://127.0.0.1:<local_port>
```

服务应在远端绑定 `127.0.0.1`，本地转发也显式绑定回环；此时无需额外开放服务端口。隧道需要 SSH 转发策略允许，并不会代替 Jupyter/Web UI 的认证。`ExitOnForwardFailure` 检查转发建立，不能保证最终目标服务可达。

## 修改后的检查

防火墙规则修改后，至少检查三件事：

```bash
sudo ufw status verbose
ss -lntp
curl -I --max-time 10 http://127.0.0.1:<port>
```

如果是远程访问，还需要在客户端测试：

```bash
nc -vz <server_address> <port>
```

本机 curl 只检查本机服务响应，不证明远端防火墙生效。应分别从允许和不允许的来源核对预期结果，并检查 IPv6 监听、容器发布端口及上游网络策略。

## 注意事项

- 不要执行 `sudo ufw deny 22/tcp`，除非已经确认有其它登录入口。
- 不要长期开放调试端口。
- 不要把 `0.0.0.0` 上的 Web 服务当成内部服务使用。
- 对外服务必须确认认证、日志和更新策略。
- 修改规则后建议记录修改原因、端口号、负责人和预计关闭时间。

依据：[Ubuntu 防火墙文档](https://ubuntu.com/server/docs/how-to/security/firewalls/)、[OpenSSH 转发配置](https://man.openbsd.org/ssh_config)。
