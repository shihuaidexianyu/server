# 防火墙

服务器默认只开放 SSH 所需的 `22` 端口，其它端口默认关闭。这样做是为了减少被扫描、误访问和弱口令攻击的风险。即使服务器位于校内网络，也不能假设校内网络是可信环境。

## 基本原则

- 默认不开放端口，只有明确需要时才开放。
- 优先只对校内网段、指定机器或指定用户开放访问。
- 临时调试端口用完后及时关闭。
- 不要把 Jupyter、TensorBoard、Web 服务等直接暴露到所有地址，优先使用 SSH 端口转发。
- 修改防火墙前先确认自己有备用登录方式，避免误操作把 SSH 也锁住。

## 查看防火墙状态

Ubuntu 上通常使用 `ufw` 管理防火墙：

```bash
sudo ufw status verbose
sudo ufw status numbered
```

如果系统提示 `inactive`，说明 `ufw` 未启用。启用前必须先允许 SSH：

```bash
sudo ufw allow 22/tcp
sudo ufw enable
```

## 开放端口

临时开放一个端口时，先确认服务确实监听在该端口：

```bash
ss -lntp
```

开放 TCP 端口示例：

```bash
sudo ufw allow 8888/tcp
```

如果只允许某个来源 IP 访问，推荐写得更严格：

```bash
sudo ufw allow from 10.0.0.25 to any port 8888 proto tcp
```

其中 `10.0.0.25` 替换为实际允许访问的客户端 IP。

## 关闭端口

查看规则编号：

```bash
sudo ufw status numbered
```

按编号删除规则：

```bash
sudo ufw delete <rule_number>
```

也可以按规则内容删除：

```bash
sudo ufw delete allow 8888/tcp
```

## 推荐做法：使用 SSH 端口转发

如果只是自己访问服务器上的 Jupyter、TensorBoard 或 Web UI，不建议开放公网或校内网端口。可以在本机执行：

```bash
ssh -L <local_port>:127.0.0.1:<remote_port> <server_alias>
```

然后在本机浏览器打开：

```text
http://127.0.0.1:<local_port>
```

这样服务只通过 SSH 隧道访问，不需要额外开放服务器防火墙端口。

## 修改后的检查

防火墙规则修改后，至少检查三件事：

```bash
sudo ufw status verbose
ss -lntp
curl -I http://127.0.0.1:<port>
```

如果是远程访问，还需要在客户端测试：

```bash
nc -vz <server_address> <port>
```

## 注意事项

- 不要执行 `sudo ufw deny 22/tcp`，除非已经确认有其它登录入口。
- 不要长期开放调试端口。
- 不要把 `0.0.0.0` 上的 Web 服务当成内部服务使用。
- 对外服务必须确认认证、日志和更新策略。
- 修改规则后建议记录修改原因、端口号、负责人和预计关闭时间。
