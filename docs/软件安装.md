# 软件安装

服务器上有一些面向所有用户的公共脑影像软件，例如 AFNI、FSL、FreeSurfer 等。本文只记录系统级公共软件的安装位置、环境变量和维护边界。

个人 Python/R 依赖、项目私有软件和 pip/conda 包安装，不放在本文维护。请严格参考 [Conda 环境](conda环境.md)，禁止直接使用系统 `pip` 或 `sudo pip` 安装个人依赖。

## 公共软件的使用原则

- 公共软件尽量只读使用，不随意修改安装目录。
- 需要升级或重装公共软件时，先通知正在使用该软件的成员。
- 不确定软件路径时，先查询环境变量和可执行文件位置。
- 个人实验依赖不要直接装进系统 Python 或系统目录。
- 个人依赖统一使用 [Conda 环境](conda环境.md) 管理。

## 查看软件是否可用

登录服务器后，可以用以下命令检查软件命令是否已经在 `PATH` 中：

```bash
which afni
which fsl
which recon-all
```

也可以查看版本：

```bash
afni -ver
fslversion
recon-all -version
```

如果命令不存在，说明当前 shell 没有加载对应软件环境，或者软件没有安装到公共路径中。

## 建议记录的公共软件信息

管理员应维护下面信息，方便用户和 AI agent 判断环境：

| 软件 | 安装路径 | 主要命令 | 环境变量 | 维护人 | 备注 |
| --- | --- | --- | --- | --- | --- |
| AFNI | `/opt/afni` | `afni` | 已加入全局 `PATH` | 管理员 | 基础脑影像分析 |
| FSL | `/opt/fsl` | `fsl`, `fslmaths` | `FSLDIR=/opt/fsl` | 管理员 | 需通过 `fsl.sh` 加载环境 |
| FreeSurfer | `/opt/freesurfer` | `recon-all` | `FREESURFER_HOME=/opt/freesurfer`, `SUBJECTS_DIR` | 管理员 | 结构像皮层重建 |

## 常见环境变量

FSL 常见配置形式如下，具体路径以服务器实际安装位置为准：

```bash
export FSLDIR=/path/to/fsl
source "$FSLDIR/etc/fslconf/fsl.sh"
export PATH="$FSLDIR/bin:$PATH"
```

FreeSurfer 常见配置形式如下：

```bash
export FREESURFER_HOME=/path/to/freesurfer
source "$FREESURFER_HOME/SetUpFreeSurfer.sh"
```

如果这些配置需要对所有用户生效，可以放入 `/etc/bash.bashrc`，但必须先测试不会拖慢登录或输出多余内容。全局 Bash 配置参见 [bash继承.md](bash继承.md)。

## 安装前需要确认

安装新软件前，先确认下面几件事：

1. 软件是否已经有公共版本。
2. 是否需要管理员权限。
3. 是否会占用大量 `/data` 或系统盘空间。
4. 是否需要联网下载，是否要开启代理。
5. 是否会修改全局环境变量。
6. 是否会影响已有实验的可重复性。

普通用户安装个人软件前，应先阅读 [Conda 环境](conda环境.md)，不要把个人依赖写入公共软件目录。

## 软件不可用时的排查

先检查命令是否存在：

```bash
which 命令名
echo "$PATH"
```

再检查环境变量：

```bash
env | grep -E 'FSL|FREESURFER|AFNI'
```

如果是权限问题，检查文件权限：

```bash
ls -ld /path/to/software
ls -l /path/to/software/bin
```

如果是联网安装失败，先确认普通网络和代理网络是否可用，参见 [一般网络连接.md](一般网络连接.md) 和 [代理网络连接.md](代理网络连接.md)。

## 维护建议

- 公共软件目录只允许管理员写入。
- 大版本升级前保留旧版本路径。
- 对实验结果影响大的软件应记录版本号。
- 用户脚本中尽量显式写清软件版本和环境名称。
- 发现公共软件损坏时，不要自行覆盖安装，先联系管理员。
