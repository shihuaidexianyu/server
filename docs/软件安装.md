# 公共软件使用

服务器可能部署面向所有用户的公共脑影像软件，例如 AFNI、FSL、FreeSurfer 等。软件是否已经安装、当前版本和真实路径，必须以登录目标服务器后的检测结果为准。

个人 Python/R 依赖、项目私有软件和 pip/conda 包安装，不放在本文维护。请严格参考 [Conda 环境](conda环境.md)，禁止直接使用系统 `pip` 或 `sudo pip` 安装个人依赖。

> **【说明】适用对象与完成标准**
>
> - **适用对象**：需要调用公共脑影像软件的普通用户，以及维护公共安装的管理员。
> - **前置条件**：已经登录目标服务器，并知道实验所需的软件名称和版本要求。
> - **所需权限**：普通用户只读调用；安装、升级和修改全局环境仅限管理员。
> - **完成标准**：命令路径、版本和必要环境变量均已确认，并完成一个不会写入公共目录的最小测试。

## 公共软件的使用原则

- 公共软件尽量只读使用，不随意修改安装目录。
- 需要升级或重装公共软件时，先通知正在使用该软件的成员。
- 不确定软件路径时，先查询环境变量和可执行文件位置。
- 个人实验依赖不要直接装进系统 Python 或系统目录。
- 个人依赖统一使用 [Conda 环境](conda环境.md) 管理。

## 查看软件是否可用

登录服务器后，先批量检查主要命令是否位于 `PATH`：

```bash
for cmd in afni fslmaths recon-all; do
  if command -v "$cmd" >/dev/null 2>&1; then
    printf '%-12s %s\n' "$cmd" "$(command -v "$cmd")"
  else
    printf '%-12s %s\n' "$cmd" "NOT FOUND"
  fi
done
```

也可以逐项检查：

```bash
command -v afni
command -v fslmaths
command -v recon-all
```

也可以查看版本：

```bash
afni -ver
cat "$FSLDIR/etc/fslversion"
recon-all -version
```

如果命令不存在，说明当前 shell 没有加载对应软件环境，或者软件没有安装到公共路径中。

## 常见加载方式

下面是软件常见的加载形式，仅用于理解变量含义，不代表服务器的真实安装路径。

FSL 示例：

```bash
export FSLDIR=/path/to/fsl
source "$FSLDIR/etc/fslconf/fsl.sh"
export PATH="$FSLDIR/share/fsl/bin:$PATH"
```

当前 FSL 官方建议使用 `share/fsl/bin` 中的 wrapper，避免 `bin` 里的 Python/Conda 抢占项目环境；旧安装布局须依据相应版本，不要仅因这个目录不存在就推定未安装。`FSLDIR` 必须先确认再读取版本文件。

FreeSurfer 示例：

```bash
export FREESURFER_HOME=/path/to/freesurfer
source "$FREESURFER_HOME/SetUpFreeSurfer.sh"
```

管理员应按使用方式选择模块、项目加载脚本或系统启动文件；仅写入 `/etc/bash.bashrc` 不保证所有非交互脚本都加载。必须测试不会拖慢登录或输出多余内容。全局 Bash 配置参见 [Bash 继承](bash继承.md)。

普通用户不要凭示例猜测路径并写入 `~/.bashrc`。应先使用 `command -v`、`echo "$FSLDIR"` 或 `echo "$FREESURFER_HOME"` 确认真值。

## 安装前需要确认

安装新软件前，先确认下面几件事：

1. 软件是否已经有公共版本。
2. 是否需要管理员权限。
3. 是否会占用大量 `/data` 或系统盘空间。
4. 是否需要联网下载，是否要开启代理。
5. 是否会修改全局环境变量。
6. 是否会影响已有实验的可重复性。

普通用户安装个人软件前，应先阅读 [Conda 环境](conda环境.md)，不要把个人依赖写入公共软件目录。

## 软件不可用时的排查

先检查命令是否存在：

```bash
command -v <command_name>
echo "$PATH"
```

再检查环境变量：

```bash
env | grep -E 'FSL|FREESURFER|AFNI'
```

如果是权限问题，检查文件权限：

```bash
ls -ld /path/to/software
ls -l /path/to/software/bin
```

如果是联网安装失败，先确认普通网络和代理网络是否可用，参见 [一般网络连接](一般网络连接.md) 和 [代理网络连接](代理网络连接.md)。

反馈问题时应提供：

```bash
hostname
whoami
command -v <command_name>
echo "$PATH"
```

同时附上所需软件、目标版本、失败命令和报错；对外发日志前遮盖内部主机名、路径与凭据。

## 维护建议

- 公共软件目录只允许管理员写入。
- 大版本升级前保留旧版本路径。
- 对实验结果影响大的软件应记录版本号。
- 用户脚本中尽量显式写清软件版本和环境名称。
- 发现公共软件损坏时，不要自行覆盖安装，先联系管理员。
- 修改事实表时同时记录目标服务器和验证日期。
