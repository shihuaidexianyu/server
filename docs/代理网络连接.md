# 代理网络连接

当前代理服务器架设在 `xiphos` 上，使用 `mihomo` 和 `zashboard` 完成代理中转。需要代理的服务器可以使用 `pon` 和 `poff` 函数开启或关闭当前 shell 的代理环境。

本文是代理使用流程页。`pon`、`poff` 为什么能被所有 Bash 用户继承，见进阶原理页 [Bash 继承](bash继承.md)。

## 工作原理

`pon` 和 `poff` 通过修改 shell 环境变量来控制代理：

- `pon`：向当前 shell 注入代理环境变量。
- `poff`：清理当前 shell 中的代理环境变量。

支持代理环境变量的程序会自动通过代理访问网络，例如 `curl`、`git`、`pip`、部分 `npm` 命令等。

常见环境变量包括：

```bash
http_proxy
https_proxy
all_proxy
HTTP_PROXY
HTTPS_PROXY
ALL_PROXY
```

## 开启代理

在需要联网的 shell 中执行：

```bash
pon
```

检查代理变量是否生效：

```bash
env | grep -i proxy
```

测试出口 IP：

```bash
curl ipinfo.io
```

如果 `pon` 前后 IP 归属地不同，通常说明代理已经生效。

## 关闭代理

当前任务完成后执行：

```bash
poff
```

确认代理变量已经清理：

```bash
env | grep -i proxy
```

如果没有输出，说明当前 shell 中已没有代理变量。

## 常见使用场景

### Git

```bash
pon
git clone https://github.com/example/repo.git
poff
```

### pip

```bash
pon
pip install <package_name>
poff
```

### Conda

```bash
pon
conda install <package_name>
poff
```

### npm 或 nvm

```bash
pon
npm install -g <package_name>
poff
```

AI CLI 工具的 Node.js 依赖安装参见 [AI使用.md](AI使用.md)。

## 在脚本中使用

不建议在长期脚本中默认开启代理。更稳妥的方式是在运行脚本前手动开启：

```bash
pon
bash run_download.sh
poff
```

如果脚本必须使用代理，应在脚本开头清楚写明依赖，并在结束时恢复环境。

## 常见问题

### 执行 pon 后命令不存在

说明当前用户没有继承全局 Bash 配置，或者不是 Bash shell。检查：

```bash
echo "$SHELL"
type pon
```

相关配置参见 [bash继承.md](bash继承.md)。

如果你在 VS Code Remote SSH 的远程终端中遇到这个问题，先确认远程终端使用的是 Bash，再新开一个终端窗口重新测试。

### curl 可以代理，但某个程序不走代理

说明该程序可能不读取标准代理环境变量。需要查看该程序自己的代理配置方式。例如某些工具需要单独设置配置文件。

### 代理开启后内网访问异常

有些内网地址不应该走代理，需要设置 `no_proxy`。具体配置取决于实际代理规则，建议由管理员统一维护。

### 代理不稳定

先确认代理服务所在服务器是否正常，再检查本机变量：

```bash
curl ipinfo.io
env | grep -i proxy
```

如果多名用户同时异常，可能是 `xiphos` 上的 `mihomo` 或上游网络异常。

## 安全提醒

- 不要把代理地址、token 或订阅信息写入共享文档。
- 不要把 `pon` 写入所有脚本的默认启动逻辑。
- 代理只解决网络访问问题，不等于绕过软件许可或数据合规要求。
- 下载大文件前确认来源可靠、磁盘空间足够。
