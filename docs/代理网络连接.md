# 代理网络连接

原部署记录称实验室代理由内部代理主机提供，真实主机名和管理地址保存在管理员私有清单中。需要代理的服务器可以使用 `pon` 和 `poff` 函数开启或关闭当前 shell 的代理环境。

> **【说明】适用对象与完成标准**
>
> - **适用对象**：基础网络正常，但需要访问特定外部软件源或服务的用户。
> - **前置条件**：已完成普通网络认证，当前 shell 使用 Bash，并能执行 `pon` 和 `poff`。
> - **完成标准**：开启后代理变量存在且目标服务可访问；关闭后用于代理转发的变量按函数约定被清理，目标请求按预期直连；`no_proxy` 可仍存在。

本文是代理使用流程页。`pon`、`poff` 在哪些 Bash 启动方式下能被加载，见进阶原理页 [Bash 继承](bash继承.md)。

## 工作原理

`pon` 和 `poff` 通过修改 shell 环境变量来控制代理：

- `pon`：向当前 shell 注入代理环境变量。
- `poff`：清理当前 shell 中的代理环境变量。

是否走代理取决于程序、协议、自身配置和 `no_proxy`；支持这些变量的程序包括例如 `curl`、`git`、`pip`、部分 `npm` 命令等。

常见环境变量包括：

```bash
http_proxy
https_proxy
all_proxy
HTTP_PROXY
HTTPS_PROXY
ALL_PROXY
```

## 开启代理

在需要联网的 shell 中执行：

```bash
pon
```

检查代理变量是否生效：

```bash
env | cut -d= -f1 | grep -i proxy
```

测试出口 IP：

```bash
curl --max-time 10 https://ipinfo.io/ip
```

出口 IP 改变可作为一次请求路径变化的线索；出口相同也可能走了代理，不同也不能证明所有程序都走代理。还须测试实际目标服务，必要时在本地查看 `curl -v` 的连接信息并遮盖凭据。

## 关闭代理

当前任务完成后执行：

```bash
poff
```

确认代理变量已经清理：

```bash
env | cut -d= -f1 | grep -i proxy
```

列表无输出只说明环境中没有名称包含 proxy 的变量；它不能排除程序配置文件或透明代理。若仍保留 `no_proxy`/`NO_PROXY`，并不表示转发代理仍开启。

## 常见使用场景

### Git

```bash
pon
git clone https://github.com/example/repo.git
poff
```

### pip

```bash
pon
python -m pip install <package_name>
poff
```

### Conda

```bash
pon
conda install <package_name>
poff
```

### npm 或 nvm

```bash
pon
npm install -g <package_name>
poff
```

具体 AI CLI 是否需要 Node.js 依安装方式而定，参见 [AI 使用](AI使用.md)。

## 在脚本中使用

不建议在长期脚本中默认开启代理。更稳妥的方式是在运行脚本前手动开启：

```bash
pon
bash run_download.sh
poff
```

导出的代理变量会传给随后启动的脚本；函数定义本身不会默认传给非交互 Bash。只需临时作用于一个任务时，可在已加载函数的交互 Bash 使用子 shell：

```bash
(pon && bash run_download.sh)
```

子 shell 结束后，父 shell 的变量保持原值，无需用 `poff` 猜测恢复原来配置。`pon` 的返回码和变量名仍以部署脚本为准。

## 常见问题

### 执行 pon 后命令不存在

可能未部署函数、当前 shell 不是 Bash，或启动文件未加载。检查：

```bash
ps -p $$ -o comm=
type -t pon
```

相关配置参见 [Bash 继承](bash继承.md)。

如果你在 VS Code Remote SSH 的远程终端中遇到这个问题，先确认远程终端使用的是 Bash，再新开一个终端窗口重新测试。

### curl 可以代理，但某个程序不走代理

说明该程序可能不读取标准代理环境变量。需要查看该程序自己的代理配置方式。例如某些工具需要单独设置配置文件。

### 代理开启后内网访问异常

有些内网地址不应该走代理，需要设置 `no_proxy`。具体配置取决于实际代理规则，建议由管理员统一维护。

### 代理不稳定

先确认代理服务所在服务器是否正常，再检查本机变量：

```bash
curl --max-time 10 https://ipinfo.io/ip
env | cut -d= -f1 | grep -i proxy
```

如果多名用户同时异常，可能是内部代理服务或上游网络异常，应由管理员检查代理主机。

## 安全提醒

- 不要把代理地址、token 或订阅信息写入共享文档。
- 不要把 `pon` 写入所有脚本的默认启动逻辑。
- 代理只解决网络访问问题，不等于绕过软件许可或数据合规要求。
- 下载大文件前确认来源可靠、磁盘空间足够。

`curl` 对 HTTP 代理只读取小写 `http_proxy`，HTTPS 使用 `https_proxy`/`HTTPS_PROXY`，并受 `no_proxy`/`NO_PROXY` 影响。代理地址常用 `http://...`，即使请求目标是 HTTPS；协议写法应按代理实际支持的方式。Git 的 HTTPS 与 SSH 传输路径也不同，不能把一次 HTTPS clone 结果泛化到 SSH。

依据：[curl 代理变量](https://curl.se/docs/manpage.html)、[Bash 环境与函数](https://www.gnu.org/s/bash/manual/bash.html)。
